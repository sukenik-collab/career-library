# Intro lookup: who can get the user in

Optional. Run this when the user names a company or shares a posting and
asks who they know there. It needs at least one contact source in the
project. If there is none, say so and stop.

## Sources, in this order

1. **A connections export** the user has added to the project, such as
   the connections file a professional network lets them download. Match
   on the company column.
2. **Any other contact list** the user has added. Match loosely: case,
   spacing, legal suffixes, known aliases. Show any notes the list
   carries.
3. **Email history,** only if an email connection is available. Search
   the company's email domain and the names found in 1 and 2. Subject
   lines and snippets only; open a thread only to see who wrote last.
   Ignore job alerts, newsletters, and mass recruiter mailings.

Say plainly when a source is missing or unreadable. Don't skip it
silently.

## Before looking

Identify the company. If the posting is from a recruiter or agency and
the employer is unnamed, say so, don't guess the employer, and look up
only the recruiter.

## Report, warmest first

For each person:

- Name, source, role and company if known, and how to reach them.
- Warmth:
  - **WARM**: two-way email within the last two years.
  - **STALE**: two-way email, older. Give the year.
  - **COLD**: one-way contact, or none.
  - **LISTED**: appears on a contact list but the user doesn't know
    them.
- One line of context from the email history, if any.
- A recommended first move.

## Rules

- Never claim a relationship the data doesn't show. "Emailed in 2011" is
  not "knows me."
- A person who knows the user and can forward to someone near the hiring
  decision usually ranks above a senior stranger.
- One route at a time. Hold the second as a fallback.
- An intro message promises a CV, so the tailored CV comes first.
- Write referral and forwarding messages to stand alone after any
  personal opener is removed.
- If a lookup turns up a correction (someone has moved companies), note
  it and ask whether to update the list.
- Don't store email content anywhere.

## Afterwards

If `pipeline.md` exists and the user decides to pursue the role, add it
there (`method-pipeline.md`) as "considering", with the route and contact
they chose. If it's already there, update the route and contact.
